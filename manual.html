O ciclo de desenvolvimento

As frequências são diferentes: configurar é por máquina, criar projeto é por projeto, o resto é recorrente.

1. Configure

registra seu nível e a pasta-base, sobe o Project Hub e entrega este manual. É por máquina, não por projeto — e pode rodar de novo quando quiser trocar o perfil.

2. Construa — por projeto

lê o perfil salvo e pergunta só o que é do projeto. Depois, . Todo código é TypeScript e explica as decisões.

3. Organize

define pastas, estado e responsabilidades na medida do projeto — sem antecipar complexidade que ele ainda não precisa.

4. Revise

verifica qualidade, acessibilidade, erros, performance e dívida técnica sem mudar comportamento sem motivo.

5. Publique

inspeciona a stack em silêncio, recomenda o provedor, valida o build e só então publica. Se o build falhar, o deploy para.

6. Acompanhe

reabre o Project Hub local em 127.0.0.1:8766. Os dados ficam em JSON no seu computador.

O fluxo do

Comando de fim de ciclo. A ordem é obrigatória e existe para não publicar build quebrado nem vazar credencial.

  1. 1. Analisar — lê package.json, lockfiles e configs para descobrir a stack. Não pergunta nada ainda.
  2. 2. Configurar — detecta o gerenciador de pacotes, confere se os .env estão no .gitignore e localiza os scripts de build e lint.
  3. 3. Validar — instala, roda lint e build. Falhou? Informa o arquivo e a possível correção, e não segue.
  4. 4. Confirmar — apresenta a recomendação e espera você escolher o provedor.
  5. 5. Deploy — checa a CLI do provedor, faz login se preciso, publica.
  6. 6. Informar — relatório com provedor, stack, status, URL e CI/CD configurado.

Provedores mapeados

Vercel · Netlify · Cloudflare Pages · GitHub Pages · Expo EAS · GitHub Actions

Recomendação por stack

Next.js → Vercel · Vite/SPA → Vercel, Netlify, Cloudflare, GH Pages · Expo mobile → EAS

Credenciais nunca vão para o código. Elas ficam no painel do provedor ou em Settings → Secrets and variables → Actions.

As skills agem sozinhas

Além dos comandos que você digita, o pacote traz uma skill de conhecimento que o assistente aciona por conta própria conforme o assunto da conversa. Elas não aparecem no menu / de propósito — são base de conhecimento, não ações: react-dev, que carrega o arquivo de referência certo conforme o assunto. Você não precisa invocá-las.

O é o oposto: só você pode disparar. Publicar em produção não parte do assistente por conta própria.

Seu perfil fica salvo

O nível de calibração é informado no e persiste em dashboard-config.json. Todos os comandos leem esse valor para ajustar a profundidade das explicações e o teto de complexidade arquitetural — nenhum deles repergunta. Para trocar de nível, rode outra vez: ele mostra o que está salvo e altera só o que você pedir.

Decisões padrão

  • React: TypeScript, Hooks, Context/Zustand e TanStack Query.
  • Next.js: App Router, Server Components e Server Actions quando adequados.
  • Mobile: Expo, Expo Router, Hermes e Reanimated.
  • Deploy: build validado antes de publicar, segredos fora do repositório.

Instalação

Claude Code (CLI)

/plugin marketplace add victoralecrim11/plugin-react-dev-toolkit
/plugin install plugin-react-dev-toolkit@react-dev-marketplace
/reload-plugins

Claude Desktop

Botão + ao lado do prompt → Plugins → Add plugin. O navegador lista os marketplaces já configurados, então adicione o marketplace uma vez pela CLI e depois gerencie pelo desktop.

Codex

O marketplace padrão fica em .agents/plugins/marketplace.json e aponta para a raiz do repositório. Adicione a raiz como marketplace local e reinicie o aplicativo.

O README.md do repositório traz as formas alternativas — URL git, tag fixada, URL direta do marketplace.json e sessões cloud.
